# План реализации чёрного списка для Minishop

Первая версия плагина — `0.1.0`. Он сопоставляет Telegram ID клиентов Minishop с настраиваемыми внешними списками, показывает совпадения в админке и уведомляет администратора о выбранных событиях. Совпадение не меняет доступ клиента, состояние подписки или обработку оплаты.

## Совместимость с Minishop 3.8.5

Проверены исходники релиза `v3.8.5` (`2b6d2ce6`). Версия поддерживает Plugin API 1 и `ui_composition` до версии 4. Проверка по исходникам определяет доступные точки расширения. Установка и работа будущего пакета входят в приёмку.

| Интерфейс | Контракт и ограничение |
| --- | --- |
| Настройки плагина | `frontend.settings_tabs` открывает собственную форму в разделе «Плагины → Настройки». Плагин сохраняет настройки в своих таблицах через админский API. |
| Столбец с красным крестиком в `/admin/users` | Штатная таблица не предоставляет точку для дополнительного столбца или метки строки. Нужна поддержка в ядре. |
| Фильтр над таблицей в `/admin/users` | Штатный интерфейс и серверный запрос не принимают фильтры плагинов. Нужны расширения формы и запроса до подсчёта и пагинации. |
| Карточка `/admin/users/{ID}` | `frontend.user_panels` добавляет вкладку, а `admin.users.detail.actions` позволяет встроить блок во вкладку «Действия». Для постоянной метки рядом с заголовком профиля нужна точка в ядре. |
| Красный крестик в списке `/admin/support` | Штатный список не предоставляет точку для метки тикета. Нужна поддержка в ядре. |
| Открытый тикет `/admin/support/{ID}` | `admin.support.ticket.content` размещает блок над редактором ответа. Слот доступен с `ui_composition: 3`, передаёт выбранный тикет и Telegram ID его автора при наличии привязки. |
| «Пользователи из blacklist» | `frontend.sections` добавляет пункт меню и страницу со штатной навигацией. На 3.8.5 переключатель плагина может отключать содержимое страницы. Скрытие самого пункта меню и вкладки карточки по сохранённой настройке требует поддержки в ядре. |

Основания проверки в Minishop — `docs/development/plugin-ui-composition.md`, `docs/development/plugins.md`, `backend/bot/plugins/package_ui_composition.py`, `frontend/src/admin/sections/runtimeExtensions.ts` и исходники штатных экранов «Пользователи» и «Поддержка».

## 1. Каркас и настройки

- Выделить Python-пакет с точкой входа `minishop.plugins`, каталог административного TypeScript-интерфейса с отдельным ESM-бандлом, каталоги локализации и скрипты сборки. Использовать `setup_web`, `migrations` и штатные фоновые задания Minishop (`durable_jobs: 1`). Изолировать стили плагина, использовать цвета и размеры темы админки.
- Добавить многострочное поле «Ссылки на списки» с одной ссылкой на строку. Включить обе стартовые ссылки в начальную конфигурацию. Показать дату последнего успешного обновления и ошибки по каждому источнику.
- Добавить отдельные переключатели для столбца и фильтра пользователей, статуса в карточке пользователя, метки в списке тикетов, статуса в открытом тикете и раздела «Пользователи из blacklist». Для недоступных на установленном ядре мест показать причину в настройках.
- Добавить поля ID чата и необязательного ID топика, а также флажки событий «Зарегистрировался», «Взял триал», «Оплатил», «Истёк» и «Все». «Все» включает четыре флажка. Включение отправки требует сохранённого ID чата и хотя бы одного события.
- Проверять админскую сессию и права в каждом обработчике. Для сохранения использовать механизм CSRF Minishop. Хранить конфигурацию на сервере, чтобы веб-процесс и воркер видели одинаковые настройки.

## 2. Загрузка и сопоставление

- Загружать источники фоновыми заданиями при первом включении, после изменения ссылок и периодически. Для первой версии запланирован интервал один час. Принимать публичные HTTPS-адреса, проверять адрес назначения перед соединением и после редиректов, ограничивать размер ответа и время скачивания.
- Разбирать UTF-8. Первый `#` отделяет числовой Telegram ID от причины. Из причины извлекать безопасные ссылки и сохранять остальной текст. Пропускать пустые строки и комментарии, учитывать число некорректных строк. Оба стартовых файла проверены. Встречаются повторные ID в одном файле, пересечения между файлами и несколько ссылок в одной записи.
- Хранить совпадения по Telegram ID и источнику, объединять точные дубли и сохранять разные причины и ссылки. Использовать отдельные таблицы плагина. Успешное обновление заменяет снимок одного источника целиком. При ошибке сохраняется его последний успешный снимок с отметкой об устаревании. Удалённый в настройках источник сразу исключается из сопоставления.
- Сопоставлять по `telegram_id` привязанного аккаунта. Показывать «Совпадений нет» после проверки всех настроенных источников. Для аккаунта без Telegram или при неполной проверке показывать соответствующий статус. Положительное совпадение отображать и при сбое другого источника, а для результата из устаревшего снимка указывать дату загрузки. В выдачу отдельной страницы включать только существующих пользователей Minishop.

## 3. Интерфейс на штатной версии

- Добавить раздел «Пользователи из blacklist» с постраничным списком совпавших клиентов и переходом в штатную карточку пользователя.
- Добавить вкладку «Чёрный список» в карточке клиента и блок статуса в открытом тикете. Для совпадения показать причины текстом и по доступной иконке на каждую ссылку. Ссылка открывается в новой вкладке. Для записи только со ссылкой достаточно статуса и иконки.
- Выдавать состояние и совпадения через пакетный запрос к админскому API. Выводить причины как обычный текст и делать иконки различимыми для клавиатуры и экранного диктора.

## 4. Уведомления в Telegram

Подписать плагин на события Minishop. Для регистрации проверить Telegram ID из события по сохранённому аккаунту. Для остальных событий получить его по внутреннему `user_id`.

| Настройка | Событие | Правило первой версии |
| --- | --- | --- |
| Зарегистрировался | `user.registered` | Регистрация с привязанным Telegram. Создание аккаунта через синхронизацию панели пропускается по примеру штатного уведомления. Последующая привязка Telegram имеет отдельное событие. |
| Взял триал | `trial.activated` | Успешная активация триала. |
| Оплатил | `payment.succeeded` | Успешный платёж положительной суммы. Включает пополнение, покупки с баланса, покупку подарка, автопродление и платный триал. Платный триал может вызвать два разных уведомления при включённых категориях. |
| Истёк | `subscription.expired` | Истечение подписки по сигналу воркера Minishop. Воркер проверяет окно первых 24 часов и пропускает подписки, исключённые правилами Minishop, в том числе заменённые новой активной подпиской. |

- Повторить структуру штатного уведомления «👤 **Новый пользователь**» в HTML Telegram. Для совпадения показать заголовок, событие, имя и Telegram ID, время, причины и кнопку перехода в карточку. Экранировать подставляемый текст, учитывать лимит сообщения и использовать настроенный чат и топик. Боту нужны права отправки в этот чат.
- Для оплаты использовать `DurableSubscription`. Minishop сохраняет задание с `payment_db_id` в транзакции платежа. Для регистрации, триала и истечения поставить задания в ту же очередь из обработчиков шины событий. Воркер проверяет, что действие зафиксировано, актуальные настройки разрешают отправку и есть совпадение, затем обращается к Telegram. При неполной проверке и отсутствии совпадения воркер ограниченное число раз откладывает решение до загрузки источников. Ключ операции защищает от повторной постановки задания. Для истечения ключ включает идентификатор подписки и дату окончания, чтобы очередное истечение после продления считалось отдельно.
- События регистрации, триала и истечения доставляются внутри процесса. При первом запуске задания до коммита воркеру может потребоваться повторная проверка. Остановка процесса до записи задания может привести к пропуску события. Сетевой тайм-аут после принятия сообщения Telegram может привести к дублю при повторной попытке. В первом выпуске планируется обработка новых событий по мере их поступления.

Основания проверки в Minishop — `docs/architecture/events.md`, `docs/development/plugin-extensions.md`, `backend/bot/services/notification_service.py` и `backend/bot/services/subscription_notification_worker.py`.

## 5. Встраивание в штатные списки

- Добавить в ядро нейтральные точки для дополнительных меток в таблице пользователей и строках тикетов. Получать статусы одним запросом на страницу, предусмотреть мобильное представление. При отсутствии плагина, отключённой настройке или ошибке загрузки штатные экраны сохраняют работоспособность.
- Добавить контракт серверного фильтра списка пользователей. Применять фильтр вместе с поиском и прочими условиями до подсчёта и пагинации. В ключе кеша учитывать настройки фильтра и ревизию снимка. Предусмотреть «Все», «Есть совпадение» и «Совпадений нет». Состояние неполной проверки не попадает в «Совпадений нет».
- Добавить управление видимостью админских вкладок и пунктов меню на основании настроек плагина. Если статус нужен прямо в шапке карточки, добавить туда отдельный слот для метки или блока.
- При реализации оформить изменения ядра отдельно и объявить версию нового контракта. Плагин использует его только после проверки доступности. Полный набор форм показа заработает на версии Minishop с этими точками расширения.

## 6. Приёмка и выпуск

1. Проверить разбор с пустыми строками, дублями, несколькими ссылками, ошибкой скачивания и обновлением источника с удалёнными ID. Проверить, что данные предыдущей успешной загрузки сохраняются при сбое источника, а отключение источника сразу убирает его совпадения.
2. Проверить установку подписанного пакета на стабильном Minishop 3.8.5. Проверить доступ к настройкам, карточку, открытый тикет, раздел меню, светлую и тёмную темы и мобильный размер экрана. После появления новых точек проверить столбец, метки в списке тикетов и фильтр на нескольких страницах.
3. Прогнать реальные сценарии регистрации, активации триала, оплаты и истечения на стенде с тестовым ботом. Проверить чат и топик, флажок «Все», отключение отдельных событий, совпадение из двух источников, повтор события и временный отказ Telegram.
4. Собрать подписанный Ed25519 ZIP с `plugin.json`, Python-пакетом, локализациями и собранным интерфейсом. Подписывать постоянным ключом из секрета GitHub Actions. Публиковать `minishop-plugin.json`, `packages/minishop-blacklist-0.1.0.zip`, `publisher.pub` и `SHA256SUMS` вместе одним коммитом в `main`. Индекс указывает на архив в том же коммите, чтобы Minishop мог установить пакет по адресу репозитория или тега.
5. Поставить тег `v0.1.0` на коммит поставки и приложить файлы к GitHub Release. Описание и ссылка на изменения берутся из корневого [CHANGELOG.md](../CHANGELOG.md#010). Выпуск с тем же номером сохраняет прежний архив и тег. Локальные изменения оформляются коммитами в `main`. Отправка изменений и запуск публикации требуют подтверждения владельца.
